## Security, edge cases and quality

- AES-256-GCM authenticates identity via AAD, uses fresh12-byte nonce and validates a separate canonical32-byte key. Migration0002 only creates the application's erp_sessions table; schema matches SQL and migration journal. Startup does not execute migrations.
- Transactional advisory lock precedes reading/decrypting the session; SQL increments the version atomically.35s lock wait covers two15s auth deadlines plus5s margin. Business GET executes after session transaction completion. Tampering/incorrect key prevents auth callback; failure rolls back and retains the prior pair.
